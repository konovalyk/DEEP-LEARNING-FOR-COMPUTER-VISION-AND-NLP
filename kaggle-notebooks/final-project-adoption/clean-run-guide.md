# Чистовий прогін на Kaggle

Ноутбук: `final-project-adoption-clean.ipynb`.
Дослідницький ноутбук і старий submission Exp23 не змінюються.

1. Створити окремий Kaggle Notebook та імпортувати чистовик.
2. Підключити дані змагання, увімкнути GPU та Internet. Перевірити `DATA_ROOT`.
3. Залишити `RUN_SENTENCE=True`, `RUN_SENSITIVITY=True` для повного погодженого прогону.
4. Виконати Save Version → Save & Run All. Архіви Exp15–28 не потрібні.
5. Завантажити `adoption_clean_results.zip` і виконаний ноутбук для аналізу.
   Зберегти також повну папку `adoption_clean` у Kaggle Outputs: вона містить ваги,
   preprocessing та кеші фото/тексту. Малий архів містить лише CSV та JSON.

Передбачено основні 5 фолдів, окреме розбиття seed 2027 і фінальне навчання.
За стандартних налаштувань це 73 короткі навчання MLP по 2 епохи,
17 CatBoost по 800 дерев і 6 логістичних регресій, плюс витяг заморожених ознак.
Точний час залежить від GPU, диска та доступу до pretrained-ваг.

## Фінальні файли

Кожен `submissions/submission_full_*.csv` використовує моделі, заново навчені
на всіх розмічених рядках `train.csv`. Це включає локальні validation-фолди.
`test.csv` без міток використовується лише для прогнозування. Пороги беруться
з OOF основного розбиття; тестові мітки або public score для підбору не використовуються.

`submission.csv` — наперед зафіксований рецепт Exp22 після full-train навчання.
Він не є старим файлом Exp23: public 0.7550 не переноситься на нього автоматично.
Інші кандидати: DINO MLP, DINO CatBoost, first/rest з одним і трьома seed,
фіксований blend Exp22+Exp27 та інші виконані моделі.

`submission_registry.csv` містить відповідність кандидатів файлам, локальний CV QWK,
число навчальних рядків та SHA256. Поле public_score порожнє до фактичного подання.
Автоматичного подання на Kaggle немає. Вибір фінальних файлів залежить від правил змагання.

## Статус перевірки

Структура notebook і синтаксис перевірені. Синтетичний наскрізний прогін перевірив
обидва CV-розбиття, справжні MLP і LogisticRegression, калібрування, full-train,
збереження моделей/CSV, порядок sample_submission та ізоляцію TF-IDF від validation.
CatBoost у локальному тесті замінювався Ridge; pretrained-енкодери не запускалися.
Це технічна перевірка, не результат експерименту. Висновки фіналізуємо за Kaggle Outputs.
